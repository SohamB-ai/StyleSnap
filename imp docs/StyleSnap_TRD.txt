1. Overview & Scope
This Technical Requirements Document (TRD) defines the complete technical architecture, data flows, algorithms, APIs, storage schema, build toolchain, and error-handling strategy for StyleSnap — a Manifest V3 Chrome extension that extracts design systems from live web pages and produces developer-ready output for manual workflows and AI coding tools.
The TRD is version-aware. Sections marked [V1], [V2], or [V3] describe features scoped to that release. Architecture decisions made at V1 that intentionally anticipate V2/V3 are flagged accordingly.
All implementation must be fully client-side — no external API calls, no backend server, no user data transmitted off-device at any version.

5. Storage Architecture
5.1  Two-Tier Strategy
StyleSnap uses two storage tiers depending on data size and type:
Tier 1 — chrome.storage.local: structured metadata, settings, extraction history references (max ~4.8 MB, well within 5 MB default limit for metadata alone)
Tier 2 — IndexedDB (via idb v8): binary blobs (screenshots), large extraction payloads (full DOM analysis data), and component code libraries

5.4  Service Worker Ephemeral State Warning
MV3 service workers are event-driven and terminate when idle (typically 30 seconds after last event). No in-memory state can be assumed to persist between events. All intermediate state during multi-step operations (scroll-stitch screenshot, full DOM walk) must either:
Be held in the content script's memory (which persists as long as the tab is open), OR
Be committed to IndexedDB before the service worker could be terminated
The screenshot pipeline keeps scroll-position state in the content script and sends completed tile blobs directly to the side panel via port messaging to avoid service worker memory constraints.

7. Token Extraction Engine  [V1]
The extraction engine runs in the ISOLATED world content script. It executes in three phases to maximise accuracy across all CSS authoring strategies (vanilla CSS, CSS variables, Tailwind utility classes, CSS-in-JS).
7.1  Phase 1 — Stylesheet Scan (Declared Styles)
Iterates document.styleSheets to extract explicitly declared CSS custom properties (variables) and @media breakpoints. This is the highest-fidelity source for intentional design tokens.
function scanStylesheets() {  const vars: Record<string, string> = {};  const breakpoints: number[] = [];  for (const sheet of document.styleSheets) {    let rules: CSSRuleList;    try {      rules = sheet.cssRules;  // throws SecurityError for cross-origin sheets    } catch { continue; }    for (const rule of rules) {      // Extract CSS custom properties from :root and * selectors      if (rule instanceof CSSStyleRule) {        if (rule.selectorText === ":root" || rule.selectorText === "*") {          const style = rule.style;          for (let i = 0; i < style.length; i++) {            const prop = style[i];            if (prop.startsWith("--")) {              vars[prop] = style.getPropertyValue(prop).trim();            }          }        }      }      // Extract breakpoints from @media rules      if (rule instanceof CSSMediaRule) {        const match = rule.conditionText.match(/\d+px/g);        if (match) breakpoints.push(...match.map(v => parseInt(v)));      }    }  }  return { vars, breakpoints: [...new Set(breakpoints)].sort((a,b) => a-b) };}
7.2  Phase 2 — DOM Walk (Computed Styles)
Walks every visible DOM element and calls getComputedStyle() to collect actual rendered values. This works regardless of whether the site uses CSS variables, Tailwind utility classes, or CSS-in-JS — because computed styles represent the final resolved values the browser uses to paint the page.
const SAMPLE_LIMIT = 2000;  // Performance: sample up to 2000 elementsfunction walkDOM() {  const colors = new Map<string, number>();   // value → frequency count  const fonts = new Map<string, FontEntry>();  const spacings = new Map<number, number>(); // px value → frequency  const radii = new Set<string>();  const shadows = new Set<string>();  const elements = Array.from(document.querySelectorAll("*"))    .filter(el => isVisible(el))    .slice(0, SAMPLE_LIMIT);  for (const el of elements) {    const cs = getComputedStyle(el);    // Colors — 5 sources per element    for (const prop of ["color","backgroundColor","borderColor","outlineColor","fill"]) {      const val = cs.getPropertyValue(prop);      if (val && val !== "rgba(0, 0, 0, 0)" && val !== "transparent") {        colors.set(normalizeColor(val), (colors.get(normalizeColor(val)) || 0) + 1);      }    }    // Typography    const ff = cs.fontFamily.split(",")[0].trim().replace(/["]/g, "");    const fs = parseFloat(cs.fontSize);    const fw = cs.fontWeight;    const lh = cs.lineHeight;    fonts.set(`${ff}-${fs}-${fw}`, { family: ff, size: fs, weight: fw, lineHeight: lh, count: ... });    // Spacing (padding/margin — extract numeric values)    for (const prop of ["paddingTop","paddingRight","paddingBottom","paddingLeft",                         "marginTop","marginRight","marginBottom","marginLeft"]) {      const v = parseFloat(cs[prop]);      if (v > 0) spacings.set(v, (spacings.get(v) || 0) + 1);    }    // Border radius & shadows    const br = cs.borderRadius;    if (br && br !== "0px") radii.add(br);    const bs = cs.boxShadow;    if (bs && bs !== "none") shadows.add(bs);  }  return { colors, fonts, spacings, radii, shadows };}
7.3  Phase 3 — Deduplication & Normalization
Raw computed values contain hundreds of near-duplicates (e.g., rgba(79, 70, 229, 1) and #4F46E5 are the same color). Phase 3 normalizes, deduplicates, and ranks by frequency to produce a clean token set.
Colors: normalize all to HSL for deduplication; cluster colors within ±5° hue + ±10% saturation + ±10% lightness as "same"; classify into semantic groups (primary, secondary, accent, neutral, semantic/status) by hue and usage context (text vs background)
Typography: deduplicate by family+size+weight; identify type scale by sorting by size and labeling h1–h6 + body + caption + micro
Spacing: identify the geometric progression (if values follow 4px grid: 4, 8, 12, 16, 24, 32, 48, 64); normalize to the base unit; flag non-grid values as "anomalous"
Shadows: deduplicate exact matches; categorize into elevation levels (none, sm, md, lg, xl) by blur-radius magnitude
Border radii: deduplicate; classify as none/sm/md/lg/full by px value

8.2  CSS Property Extraction
extractRelevantCSS() returns only non-default, non-inherited values to avoid flooding the output. It compares computed style against a baseline empty element's styles and returns only properties that differ.

10. Screenshot Pipeline  [V2]
chrome.tabs.captureVisibleTab() only captures the visible viewport. Full-page screenshots require a scroll-and-stitch approach: the content script controls the page scroll, and the service worker captures each viewport tile.
10.1  Scroll-and-Stitch Algorithm
// In content script (ISOLATED world):async function captureFullPage() {  const pageHeight = document.documentElement.scrollHeight;  const viewportHeight = window.innerHeight;  const totalTiles = Math.ceil(pageHeight / viewportHeight);  const tiles: string[] = [];  // Disable smooth scroll for clean stitching  document.documentElement.style.scrollBehavior = "auto";  // Hide sticky headers (they re-appear on every tile otherwise)  const stickyEls = findStickyElements();  stickyEls.forEach(el => el.style.display = "none");  for (let i = 0; i < totalTiles; i++) {    window.scrollTo(0, i * viewportHeight);    await sleep(150);  // allow paint to settle    // Request service worker to capture the current viewport    const dataUrl = await chrome.runtime.sendMessage({ type: "CAPTURE_SCREENSHOT" });    tiles.push(dataUrl);  }  // Restore page state  stickyEls.forEach(el => el.style.display = "");  window.scrollTo(0, 0);  document.documentElement.style.scrollBehavior = "";  // Stitch in side panel using OffscreenCanvas  chrome.runtime.sendMessage({ type: "STITCH_TILES", payload: { tiles, pageHeight, viewportHeight } });}
10.2  Stitching (Side Panel)
// In side panel (extension page with full canvas access):async function stitchTiles(tiles: string[], pageH: number, viewH: number) {  const canvas = document.createElement("canvas");  const img0 = await loadImage(tiles[0]);  canvas.width = img0.naturalWidth;  canvas.height = pageH * (img0.naturalWidth / window.screen.width);  const ctx = canvas.getContext("2d")!;  for (let i = 0; i < tiles.length; i++) {    const img = await loadImage(tiles[i]);    ctx.drawImage(img, 0, i * img.naturalHeight);  }  canvas.toBlob((blob) => {    // Store blob in IndexedDB via service worker message    chrome.runtime.sendMessage({ type: "STORE_SCREENSHOT", payload: blob });  }, "image/png");}
10.3  Known Edge Cases
Infinite scroll / lazy-loading: scroll-and-stitch stops when scrollHeight stops increasing after each scroll step (max 50 tiles to prevent infinite loop)
Parallax sections: sticky elements are hidden during capture to prevent double-rendering artifacts
Full-viewport 3D/WebGL: canvas elements are captured as static frames (the live WebGL state is not reconstructed)
iframes: cross-origin iframes render as blank regions (browser security restriction)

11.2  Confidence Threshold
An element is classified as a component only if its cumulative signal score ≥ 0.60. Elements scoring 0.45–0.59 are flagged as "uncertain" and shown with a warning indicator in the UI. Elements below 0.45 are discarded.
11.3  Repeated Structure Detection Algorithm
function getStructureSignature(el: Element): string {  // Generate a compact "fingerprint" of the element's inner structure  // using tag names and child counts only (not classes/IDs — those vary per instance)  const tag = el.tagName.toLowerCase();  const childSigs = Array.from(el.children)    .map(child => getStructureSignature(child))    .join(",");  return childSigs ? `${tag}(${childSigs})` : tag;}function findRepeatedComponents(): ComponentPattern[] {  const sigMap = new Map<string, Element[]>();  for (const el of document.querySelectorAll("*")) {    if (el.children.length < 2) continue;  // ignore leaf nodes    const sig = getStructureSignature(el);    const existing = sigMap.get(sig) || [];    existing.push(el);    sigMap.set(sig, existing);  }  // Pattern = signature appearing 3+ times  return [...sigMap.entries()]    .filter(([_, els]) => els.length >= 3)    .map(([sig, els]) => ({ signature: sig, instances: els, count: els.length }));}
11.4  Component Code Extraction
For each detected component, StyleSnap outputs:
HTML snippet: el.outerHTML of the first clean instance (long text truncated to 80 chars, src attributes normalized to placeholder)
CSS block: all non-default computed styles of the element and its children, formatted as a scoped CSS rule set
Component label: derived from ARIA role > semantic tag > class keyword match (in priority order)
Instance count: how many times this pattern appears on the page

15. Layout Structure Extraction  [V2]
15.1  Section Detection
The layout extractor identifies top-level page sections by scanning the DOM for major structural landmarks, then describes their grid/flex structure.
Detection order: semantic HTML5 landmarks first (<header>, <nav>, <main>, <footer>, <section>, <aside>), then large non-semantic divs with full-width layout (width > 80% viewport, height > 200px)
Each section is labelled by heuristic: <header> + first child nav → "Navigation"; large hero-height section with heading + button → "Hero"; grid of 3+ similar children → "Feature Grid"; etc.
Grid/flex analysis: read display, grid-template-columns, flex-direction, gap, align-items, justify-content from computed style of the section and its direct children
15.2  Output: LayoutStructure Type
interface LayoutStructure {  sections: PageSection[];  maxWidth: string;       // max content width detected  baseGrid: string;       // e.g., "12-column, 24px gap"}interface PageSection {  label: string;          // "Hero", "Navigation", "Feature Grid", "CTA", "Footer"  tagName: string;  layoutType: "flex" | "grid" | "block" | "absolute";  gridCols?: string;      // e.g., "repeat(3, 1fr)"  flexDirection?: string;  gap?: string;  padding?: string;  backgroundColor?: string;  screenshotLabel?: string;  // references section screenshot in ZIP}

18. Security Considerations
18.1  MAIN World Risk
Code executing in the MAIN world shares the page's JavaScript context and can be interfered with by the page's own scripts or other extensions. Mitigations:
MAIN world script reads globals immediately after injection and posts results back via window.postMessage within the same microtask queue — minimizing the window for interception
All postMessage communications include a source: "stylesnap-main" sentinel; the ISOLATED listener validates this before forwarding
No sensitive data (user credentials, private page content) is ever read or transmitted — only library globals and computed style values
18.2  Content Security Policy (CSP)
Sites with strict CSP may block MAIN world script injection. Specifically, if the page's CSP includes script-src 'self' without 'unsafe-inline' and without the extension origin, dynamic injection can be blocked. StyleSnap registers the MAIN world script as a web_accessible_resource which gives it the extension's own origin, bypassing most page CSP restrictions. However, some enterprise-grade sites with strict CSP header policies may still block injection — in this case, animation detection gracefully falls back to Tier 3 (DOM attribute scan only).
18.3  Data Privacy
All extraction, storage, and export happens client-side — no data is ever sent to any external server
The tabs permission (required for captureVisibleTab) is the highest-risk permission; this must be explicitly disclosed in the Chrome Web Store listing description and privacy policy
No analytics, telemetry, or usage tracking of any kind at V1–V3
Extraction history stored in chrome.storage.local is user-local and is cleared when the user uses the "Clear History" button or uninstalls the extension
