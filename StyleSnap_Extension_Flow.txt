1. How to Read This Document
This document defines every user-facing and system-level flow in StyleSnap — how data moves between the four execution contexts, what triggers each operation, what the happy path looks like step by step, and what happens when things go wrong.
Each flow follows a consistent structure:
Trigger — what initiates the flow (user action, system event, or message)
Pre-conditions — what must be true before the flow can start
Flow table — step-by-step with actor, action, data in, and data out
Decision points — forks in the flow with conditions
Error paths — what happens if the step fails
End state — what the extension looks like after the flow completes

1.2  Version Tags
Flows are tagged [V1], [V2], or [V3] matching the PRD versioning. V1 flows are fully specced; V2/V3 flows include all decision points and error paths but some implementation details are deferred to their respective milestones.
2. Extension State Machine
The extension's side panel UI can be in one of six global states at any time. All flows are transitions between these states.
State
Description
Valid Transitions
IDLE
Panel open, no extraction in progress. Showing last extraction or empty state.
→ EXTRACTING (user clicks Extract) | → INSPECTING (user activates inspector)
EXTRACTING
Full-page extraction running. Progress bar shown. Panel is non-interactive for core tabs.
→ IDLE (extraction complete) | → ERROR (extraction failed)
INSPECTING
Element inspector active on the page. Overlay visible. User hovering elements.
→ ELEMENT_SELECTED (user clicks element) | → IDLE (user presses Escape)
ELEMENT_SELECTED
Inspector result shown in panel. CSS/HTML of selected element displayed.
→ INSPECTING (user clicks Inspect Again) | → IDLE (user clicks Done)
EXPORTING
File export in progress (generating ZIP, tokens.json, etc.). Brief state — typically < 1s.
→ IDLE (export complete) | → ERROR (export failed)
ERROR
An operation failed. Error message shown with recovery options.
→ IDLE (user dismisses / retries) | → EXTRACTING (user retries extraction)

9.3  History Overflow (Auto-Eviction)
When a new extraction would push history past 10 entries, the oldest entry is automatically evicted. This runs in the SW at step 15 of Flow 3 (Full Page Extraction). The eviction deletes both the chrome.storage.local HistoryEntry and the corresponding IndexedDB records (extraction + screenshots) in a single atomic operation.
