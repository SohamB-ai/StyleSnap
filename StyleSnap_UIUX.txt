1. Design Philosophy
StyleSnap's UI is built for developers, not general consumers. This drives every design decision: density over simplicity, precision over aesthetics, and zero friction over onboarding flows.
Principle
What it means in practice
Developer-first density
Information-dense panels are fine — devs read specs. No oversimplified dashboards.
Dark-default
Most devs work in dark mode. Dark is the default; light is available but secondary.
Non-intrusive
Side panel must never visually compete with the page being inspected. Subtle borders, no animations that draw eye from the page.
Token-first styling
Every colour, spacing, radius value in the extension UI is a CSS custom property. The design system eats its own cooking.
Copy-first interactions
Every value — every hex code, every CSS property, every component snippet — is one click from the clipboard. Copy is the primary action everywhere.
Instant feedback
Every copy, export, and extraction action must confirm visually within 200ms. No wondering if it worked.
Graceful degradation
Error and empty states are first-class screens, not afterthoughts. They tell the user exactly what happened and what to do next.

7. Theme System
7.1  Implementation Strategy
Theme is implemented via CSS custom properties on the :root element of the side panel's shadow DOM. Switching theme = swapping the token values. No class toggling. No JS style manipulation beyond the single data-theme attribute.

10. Layout Edge Cases
10.1  Panel Width Behaviour
The Chrome Side Panel can be resized by the user (drag the divider between the panel and the page). StyleSnap must remain usable at all widths from 280px (minimum Chrome allows) to 600px (wide enough for two columns).
Width range
Layout adaptation
280–340px
Tab labels hidden, icons only in tab bar. Export dropdown truncates label. Colour swatches reduce to 2-column grid.
340–480px
Default layout as designed. All labels visible.
480–600px
Colour swatch grid expands to 3 columns. Component cards allow slightly wider HTML preview.
600px+
Max-width cap at 600px — content centres; padding increases.
10.2  Long Content Handling
Page titles longer than 40 characters: truncate with ellipsis in header
Hex values: never wrap — always monospace single-line
Component HTML: max-height 120px with overflow:auto (scrollable code block)
History entry URL: truncate to 36 chars + ellipsis
Font family names: wrap allowed (some system fonts have long names)
Colour names: truncate at 24 chars
